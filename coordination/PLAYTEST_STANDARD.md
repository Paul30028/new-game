# 《应许之路》共用制作与验收标准

Codex、Gemini 和 DeepSeek 使用同一套标准。每次只交付一项能检验的体验或结论。

1. **从玩家的决定出发。** 写清玩家掌握什么信息、会失去什么、两种做法分别产生什么能被观察到的后果。检查经营、模拟、建城、战斗、灵战各自是否可操作，能否影响接下来发生的事。
2. **从原始资料出发。** 需要引用时附章节与节号。把经文记述、设计推演与原创象征明确标注。区分祭司、先知和具体人物的所作所为，避免把神迹设计成可买的数值奖励。
3. **主动尝试推翻设计。** 用相同初始状态复现两条路线，一次只改变一项决策。尝试跳过系统、重复操作、耗尽物资和在关键时刻恢复存档。记录输入、预期和观察，区分实际运行、手工推演与尚未验证。
4. **交给第三方复验。** 给出可重复步骤，重视没读过设计稿的玩家能否看懂后果。源码审查可证明规则是否实现，独立盲测才用于判断体验，熟悉旧约的独立审阅者负责核对改编边界。

交付格式：结论、最有价值的反例、对应证据、优先修正、未验证事项。最多阅读任务指定的资料。涉及跨文件实现的下一轮先按用户要求列出 150 字以内计划，等确认后实施。
