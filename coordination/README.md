# 本地 AI 协作

本机制通过同一项目目录中的文件交接。当值协调者见 STATUS，默认 Codex，Gemini 可接棒协调和开发，DeepSeek 可承担开发、审查和推演。用户负责创作判断和试玩反馈。

## 最小读取顺序

1. 每个新会话读取项目入口、本文、[BRIEF.md](BRIEF.md) 和 [STATUS.md](STATUS.md)。
2. 按编号读取 `tasks/` 内分配给自己的任务，以及任务列出的必要资料。
3. 同一会话接续工作时读取变更的状态、任务和相关代码差异。仅在缺少证据时扩展搜索范围。

用户已确认方向由当值协调者更新 BRIEF。候选方案在各自任务结果中讨论，采用后再写入公共记录。STATUS 只保留当前任务、连接状态和最近验收结果，具体执行状态以任务文件为准。旧任务通过编号按需查阅。

## 一次交接

1. 当值协调者建立任务，注明负责人、目标、读取范围、允许修改的文件、验收方式与基线版本。当前起始任务为 [T001](tasks/T001.md)。
2. 指定负责人核对工作区和任务版本，将任务状态改为 `working`，再开始执行。发现同编号已有进行中的执行者时，先协调归属。
3. 执行者把交付物写入指定文件，将任务状态改为 `review`。问题和失败验证一并记录。
4. 当值协调者安排有能力执行的助手读取结果与相关差异，执行验收，将任务改为 `done` 或附上具体返工项，并更新 STATUS。

状态使用 `ready / working / review / blocked / done`。阻塞记录要写明具体依赖和已经完成的部分，依赖恢复后从该处续作。

## 写入约定

- 公共方向和状态由当值协调者维护。各执行者维护自己的任务与结果文件。
- 同一工作树的代码写任务由协调者安排顺序。需要并行编码时使用各自分支和 worktree，并由协调者整合。资料审查可同时进行。
- 扩展修改范围时，在任务中说明原因并检查其他正在进行的任务。遇到重叠修改先交给协调者处理。
- 开始与交付时记录实际提交号和相关工作区差异。版本变化后重新核对依赖接口。
- BRIEF 版本变化后，执行者检查当前任务是否受影响，在结果中记录适配情况，协调者更新任务基线。
- 所有权记录依赖执行者遵守。Git 差异与验收负责发现冲突，目录中的状态文件本身提供人工协调。

## 任务与回报格式

新任务包含编号、负责人、状态、设计版本、代码基线、目标、必要输入、修改范围、验收和结果路径。可参考 T001。

结果只需以下内容，代码、截图和长资料通过文件路径引用。

```text
任务 T001
结论 ……
交付 coordination/tasks/T001.result.md
验证 实际执行的检查与结果，或明确列出未验证内容
待处理 具体问题，没有则写“无”
```

## 控制上下文成本

- 一个任务完成一个可验收结果。提供准确文件路径、符号和必要行段。
- 聊天交接通常控制在五行，结果摘要通常控制在 500 中文字内。必要证据可超出这个目标。
- 失败输出保留相关错误片段和原日志位置。相同上下文用文件引用，减少重复粘贴。
- 只在派发、交付、阻塞或设计变更时交接。按需检查状态。
- 大型资料在首次核对后提炼带来源的结论，后续读取结论和与当前问题有关的原文。
- 节省量需要实际使用记录才能计算。角色提示、工具结果和模型自身的上下文仍会产生费用。

## 接入

本地助手应打开同一个项目目录。支持 GEMINI.md 的工具从根目录入口读取，其余本地编程工具可把“读取 AGENTS.md 并执行已分配任务”设为项目指引。网页助手可接收当前任务和引用的短资料，结果由协调者归档。

文件协议已经具备本地交接能力。独立调度程序见 [使用说明](../tools/relay/README.md)，可以启动配置好的 CLI 执行端。真实账号连接与验收状态见 STATUS。

## 限额与接棒

当前可使用人工启动的文件交接。用户指定切换，或现任协调者明确交接后，Gemini 可在 STATUS 记录接任、时间和原因。接任者核对工作区、任务状态及最后验证结果，继续已授权范围内的任务。恢复后的助手先读取当值记录。

已启动的其他助手可独立继续其任务。接管正在写代码的任务前，要确认原进程已结束或已解除写入权，并检查已有差异。没有回复时先核查运行状态，避免两个执行者同时改写。

本地调度程序已实现持久任务队列、独占领取、进程树管理、超时与限额记录、检查点提示和备用执行者调用，并完成离线故障测试。它管理自身启动的 CLI 任务，不接管现有桌面聊天。真实账号接棒仍须验收。恢复前检查改动范围，存在越界修改则保留现场并阻塞。

调度的重试次数、单任务耗时和付费调用预算需要明确配置。成本额度用完时保存进度并报告。任务变化时才调用模型，轮询和队列管理由普通程序完成。依赖用户判断的任务记录阻塞，其他独立任务可继续。

运行方案与订阅资源见 [RESOURCES.md](RESOURCES.md)。
